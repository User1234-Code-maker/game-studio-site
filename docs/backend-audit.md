# Аудит бэкенда (Node.js + подключённые API)

Проверял сервер `server/`, зависимости и всё, что сайт тянет снаружи. Ниже: что нашёл, что исправил и что оставил как рекомендацию.

## Что исправлено

| # | Находка | Чем опасно | Что сделано |
|---|---------|-----------|-------------|
| 1 | Подписка на рассылку: «прочитать файл → записать» без блокировки | Два одновременных запроса с одним адресом создавали дубль | `appendUnique` в `services/store.js` делает проверку и запись под одной блокировкой (`lib/mutex.js`). Тест: 12 запросов сразу = 1 запись |
| 2 | Ответ «You are already subscribed» | По ответу можно узнать, подписан ли чужой адрес (перебор) | Один и тот же ответ `201` для нового и существующего адреса |
| 3 | Express 4 | Ветка 4.x в режиме поддержки | Обновил до Express 5 (ошибки в async-обработчиках уходят в `errorHandler` сами) |
| 4 | Заголовки безопасности писались руками | Легко что-то забыть | `helmet` + строгий CSP, `Permissions-Policy`, HSTS в production, COOP, запрет фреймов |
| 5 | CSP держался на хэшах inline-скриптов | Хрупко: любая правка HTML ломает сайт | React-сборка без inline-скриптов: `script-src 'self'` без хэшей и `unsafe-inline` |
| 6 | В ответ на 4xx уходил `err.message` из любой ошибки | Могли утечь внутренности библиотек | Наружу идут только тексты `HttpError`; всё остальное логируется и заменяется на «Something went wrong» |
| 7 | Ошибки возвращались текстом на английском | Фронт не мог показать их на RU/ES | Стабильные коды (`validation_failed`, `rate_limited`...), фронт переводит их сам |
| 8 | Нет `unhandledRejection` / `uncaughtException`, graceful shutdown мог зависнуть | Процесс в сломанном состоянии или не завершается | Логируем, закрываем сервер, принудительный выход через 10 с |
| 9 | Нет логов запросов | Нечем разбирать проблемы | Строка на запрос с id (`X-Request-Id`), метод, путь, статус, время. Тела запросов не логируются (в них почта) |
| 10 | Настройки читались «как получится» | Опечатка в env = странное поведение | `loadConfig()` проверяет значения при старте; live-ключ Stripe не принимается без `STRIPE_ALLOW_LIVE=true` |
| 11 | Раздача статики по белому списку файлов в корне | Новые файлы легко забыть или, наоборот, открыть лишнее | Раздаётся только `client/dist`. Тест проверяет, что `package.json`, `server/`, `.env`, `storage/` не отдаются |

## Stripe (тестовая оплата)

- Цена хранится на сервере (`services/catalog.js`). Браузер присылает только id услуги, подменить сумму в DevTools нельзя (есть тест).
- Используется Checkout Session (редирект на страницу Stripe): данные карты не касаются нашего сервера и страниц, PCI-нагрузка минимальная.
- Webhook читает «сырое» тело и проверяет подпись `Stripe-Signature`. Подделка возвращает 400 (тест).
- Заказы пишутся событиями (`created` / `paid` / `expired`) с идемпотентным ключом `sessionId:type`: повторная доставка webhook не создаёт дублей (тест).
- Страница успеха не доверяет только редиректу: если webhook ещё не пришёл, сервер сам спрашивает Stripe о статусе сессии.
- Эндпоинт `/api/checkout` под rate limit, e-mail и id услуги валидируются.
- Клиент Stripe передаётся в код через параметр, поэтому тесты идут на подделке и не ходят в сеть.

## Подключённые внешние сервисы

| Сервис | Для чего | Замечание |
|--------|----------|-----------|
| Stripe Checkout | Оплата депозита | Только тестовый режим по умолчанию |
| Google Fonts | Шрифты Poppins и Montserrat | Каждый посетитель отправляет свой IP в Google. Для сайта с EU-аудиторией лучше хостить шрифты у себя (`@fontsource`) |
| Google Maps | Ссылка «Get directions» | Обычная ссылка с `rel="noopener noreferrer"`, скрипты Google не подключаются |
| GitHub Pages | Статический хостинг витрины | Бэкенда там нет: формы работают в демо-режиме, оплата выключена |

`npm audit`: 0 уязвимостей в сервере и в клиенте.

## Что осталось (рекомендации, не баги)

1. **Хранилище JSONL** годится для демо. Перед реальным трафиком заменить `services/store.js` на базу (SQLite/Postgres), интерфейс уже узкий: `append`, `appendUnique`, `readAll`.
2. **Rate limit в памяти** работает на один экземпляр. При нескольких инстансах нужен общий счётчик (Redis).
3. **Почты подписчиков лежат открытым текстом.** Для реального сайта нужны политика конфиденциальности, срок хранения и ссылка «отписаться» в письмах (GDPR).
4. **Нет админки и авторизации.** Читать сообщения и заказы можно только с диска сервера (отложено по твоей просьбе).
5. **Нет отправки писем** (чек, уведомление о заявке). Stripe уже отправляет чек, если указан e-mail.
6. **Шрифты Google** (см. таблицу выше).
7. `style-src 'unsafe-inline'` оставлен осознанно: инлайновые `style=""` двигают пины карты и стикеры. Заменить можно, но выигрыш небольшой.

## Вторая проверка (security review)

После первой правки я прогнал весь проект ещё раз как ревьюер безопасности и добавил тесты в браузере. Что нашлось дополнительно (webhook принимал сумму без сверки, нет лимита на проверку заказа, права на файлы данных, таймауты, открытый редирект на клиенте и др.), как это исправлено и что проверяет каждый тест, подробно описано в [`security-review.md`](security-review.md). Там же чек-лист перед выкладкой в прод.
