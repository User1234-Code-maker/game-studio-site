# Security review и готовность к продакшену

Ревью всего проекта целиком: сервер, клиент, платежи, зависимости, конфигурация, CI. Здесь: как проверял, что нашёл, что исправил, чем это подтверждено тестами и что остаётся на твоей стороне перед выкладкой.

Это самопроверка и автоматические тесты, а не внешний пентест. Для сайта с реальными деньгами и персональными данными стоит заказать независимый аудит.

## Как проверял

| Слой | Чем |
| --- | --- |
| Исходный код | Ручное чтение всего `server/` и клиентских мест, где есть риск: редиректы, `localStorage`, внешние ссылки, рендер пользовательского текста |
| Зависимости | `npm audit` для сервера и клиента: 0 уязвимостей. В CI то же самое на каждый push, плюс Dependabot раз в неделю |
| Сервер | `test/security.test.js`: 27 проверок по реальному HTTP (заголовки, обход путей, враждебный ввод, утечки, подделка webhook, права на файлы) |
| Браузер | Playwright (`e2e/`): настоящий Chromium, настоящий production-билд, настоящий Express. Только Stripe заменён заглушкой |
| Доступность | axe-core внутри e2e: все страницы, обе темы |

## Что проверено и оказалось в порядке

- **Подмена цены**: сумма и валюта берутся только из `catalog.js`; поля `amount`, `price`, `currency` из запроса игнорируются.
- **Return URL платежа** строятся из `PUBLIC_URL`, а не из заголовков `Host`/`Origin`/`X-Forwarded-Host`.
- **Инъекции**: объекты и массивы вместо строк (`{"$ne":""}`), CRLF в e-mail, `__proto__`, слишком длинные значения: везде 422/400, прототип не загрязняется. Базы данных нет, SQL/NoSQL-инъекциям негде работать.
- **XSS**: React экранирует всё; опасных API (`dangerouslySetInnerHTML`, `innerHTML`, `eval`) в коде нет. В e2e пять классов payload'ов вводятся в URL, поиск и формы. Скрипты не выполняются, отдельный тест подтверждает, что CSP блокирует внедрённые inline- и внешние скрипты.
- **Обход путей**: 17 вариантов (`..%2f`, `%2e%2e`, `%00`, `\`, `.env`, `.git/config`, dotfiles) ничего не отдают.
- **Утечки**: 5xx маскируются; в ответах нет стека, путей, имён библиотек и ключей. В собранном JS нет `sk_`/`whsec_` и source maps.
- **CORS** не включён: чужой сайт не прочитает ответы API. CSRF: нет cookie и сессий, а JSON-эндпоинты не разбирают `text/plain` и формы.
- **Внешние ссылки** с `target="_blank"` имеют `noopener noreferrer`.
- **Данные из `localStorage`** (язык, тема) проверяются по белому списку.
- **Размеры тел**: JSON 10 КБ, webhook 1 МБ; параллельные записи не портят файлы (40 запросов разом).

## Известные ограничения (принятые риски)

| Ограничение | Почему допустимо сейчас | Что делать при росте |
| --- | --- | --- |
| `style-src 'unsafe-inline'` | React ставит `style=""` для позиций пинов и анимаций букв; скрипты при этом строго `'self'` | Перевести на CSS-переменные/классы и убрать |
| Шрифты с Google Fonts | Внешний запрос передаёт IP посетителя Google (важно для GDPR) | Самохостинг шрифтов (`@fontsource`), затем убрать Google из CSP |
| Rate limit в памяти процесса | Достаточно для одного экземпляра | Redis при нескольких экземплярах; за Cloudflare/WAF ограничивать ещё и там |
| Данные в `storage/*.jsonl` | Для портфолио достаточно; файлы защищены правами | База данных, бэкапы, политика хранения |
| Нет капчи/honeypot на формах | Лимит 10 запросов/мин с IP + проверки | Cloudflare Turnstile, если появится спам |
| Нет админки и авторизации | Админка отложена; чтение данных только с сервера | При добавлении: сессии, CSRF-токены, 2FA, аудит заново |
| Хранение e-mail без политики конфиденциальности | Демо-проект | Страница Privacy, срок хранения, удаление по запросу |
| Если файл заказов достиг 5 МБ, новые записи падают с 503 | Защита диска; заказы не теряются, Stripe повторит webhook | Переход на базу |
| Тесты платежей идут на подделке Stripe | В песочнице нет доступа к Stripe | Один раз пройти реальный тестовый платёж локально (см. README) |
| Нет проверки в статическом режиме (GitHub Pages) через e2e | Покрыто unit-тестами (`offline` режим API-клиента) | Добавить второй e2e-проект на `vite preview` |

## Чек-лист перед выкладкой в прод

Сделай до первого публичного деплоя полной версии (с API и оплатой):

- [ ] `NODE_ENV=production`. Включает HSTS и `upgrade-insecure-requests`.
- [ ] `PUBLIC_URL=https://твой-домен` (сервер не запустится с `http://`, если включён Stripe).
- [ ] `TRUST_PROXY=1` за Render/Railway/Nginx, иначе лимит считается по IP прокси и режет всех сразу.
- [ ] HTTPS с валидным сертификатом на хостинге; редирект с http.
- [ ] Ключи Stripe только в переменных окружения хостинга, не в репозитории. `.env` в `.gitignore` (проверено).
- [ ] Webhook создан в Stripe на `https://твой-домен/api/stripe/webhook` (события `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`), секрет `whsec_...` внесён в `STRIPE_WEBHOOK_SECRET`.
- [ ] Для реальных денег: `STRIPE_ALLOW_LIVE=true` и `sk_live_...` только после полного тестового прогона и заполнения профиля Stripe (юрлицо/ИП, реквизиты).
- [ ] `STORAGE_DIR` на постоянном диске хостинга (иначе при каждом деплое файлы пропадают) + регулярный бэкап.
- [ ] Страница Privacy и согласие на хранение e-mail.
- [ ] Включены алерты/логи хостинга; проверено, что `/api/health` отвечает.
- [ ] GitHub: Settings → Pages → Source «GitHub Actions»; включить Dependabot alerts и secret scanning (Settings → Code security).
- [ ] Перед релизом: `npm run check` (серверные, клиентские, линт, e2e) и `npm run audit`.
- [ ] Проверить реальный тестовый платёж картой `4242 4242 4242 4242` на запущенном сервере.

## Как запустить проверки

```bash
npm test                 # серверные тесты, включая security.test.js
npm run test:client      # клиентские тесты
npm run lint
npm run audit            # npm audit для сервера и клиента
npm run e2e              # собирает фронт и гоняет Playwright (smoke, flows, security, a11y)
npm run check            # всё вместе
```

Первый запуск e2e: `npx playwright install chromium`. Отчёт и трейсы при падении лежат в `test-results/`.
